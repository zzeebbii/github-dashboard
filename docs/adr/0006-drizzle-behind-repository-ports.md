# ADR-0006: Drizzle behind repository ports, PostgreSQL 17

**Status:** Accepted
**Date:** 2026-08-15

## Context

We need typed database access that does not leak into the domain, on a database we can
run identically locally, in CI, and in production.

## Decision

PostgreSQL 17 with Drizzle ORM, used **only** inside
`apps/api/src/infrastructure/persistence/`. The application layer sees a
`TaskRepository` port expressed in domain terms — no rows, no SQL.

Migrations are generated by drizzle-kit, committed as plain SQL, reviewed like code,
and applied by a dedicated one-shot container — never on application start, because N
replicas booting simultaneously would race.

## Consequences

- Queries map 1:1 to SQL, so generated SQL is inspectable and predictable. This matters
  more than usual here: an agent can verify its own query intent by reading it.
- No codegen step in the inner loop, and no second source of types competing with the
  contract.
- **Known risk, accepted:** Drizzle is still `0.x` (0.45.2) after several years, and
  minor bumps have carried breaking changes. This is contained: only one directory
  imports it, so replacement is a rewrite of that directory behind unchanged port
  interfaces. Renovate treats Drizzle minor bumps as majors (never auto-merged).

## Alternatives considered

| Option   | Why not                                                                                                                                                                                                                                                                    |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Prisma 7 | Now pure TypeScript with genuinely stable versioning and excellent tooling. Rejected for the codegen step and because its generated client becomes a second source of types competing with `packages/contracts`. A reasonable alternative if the 0.x risk is unacceptable. |
| Kysely   | Purest fit for hexagonal — just typed SQL. Rejected only because migrations are hand-rolled, which is more scaffolding for a template to own.                                                                                                                              |

## Revisit when

A Drizzle upgrade breaks badly enough to cost more than the swap, or Drizzle reaches
1.0 and the risk disappears. Either way the blast radius is one directory.
